Privacy Policy

Effective date: 14 August 2026 Last updated: 20 August 2026

This policy explains what the Cloud Native Ayacucho Community (CNAYP) Discord bot (the “Bot”) does with data. It is written to describe the Bot’s actual behaviour rather than to reserve rights the Bot does not use.

The Bot is operated by Ken Esparta (“we”, “us”), the “Operator”, for the Cloud Native Ayacucho Community (CNAYP). It is used for educational and informational purposes only, as described in the Terms of Service. Contact: kenesparta@pm.me.

The Bot keeps no database. It has no persistent storage of any kind. It cannot read your messages, because it does not request the permission that would let it. Two things make it act: a command you run, and a daily timer that posts upcoming cloud native events into one channel. What it receives, it uses for that, and then discards.

What the Bot receives

Slash command interactions. When you run one of the Bot’s commands, Discord sends the Bot an interaction payload. It contains:

  • an interaction ID and a short-lived interaction token, both generated by Discord;
  • the ID of the server (guild) and channel where the command was run;
  • the name of the command and the values of any arguments you supplied.

Connection metadata. While connected, the Bot receives gateway events describing which servers it is in and whether they are available.

Public event listings. Once a day the Bot fetches two public listings of upcoming cloud native events — the CNCF community group calendar and the Linux Foundation’s conference calendar — so that it can announce them. Nothing about you is sent in those requests, and nothing about you comes back: they are the same public pages anyone can open in a browser.

What the Bot cannot see

The Bot connects with the GUILDS gateway intent only. It does not request the privileged MESSAGE CONTENT or GUILD MEMBERS intents, and it does not request permission to read a channel’s message history. In practice this means the Bot cannot read the contents of messages in your server, cannot enumerate your members, and receives nothing from your server at all unless someone explicitly invokes one of its commands. It does not read the channel it announces in, not even its own past announcements.

What is stored

Nothing is stored persistently. The Bot holds interaction data in memory only for as long as it takes to answer the command, and writes no user data to disk or to any database. So that it does not announce the same event twice, it also keeps a list of the events it has already announced; that list holds identifiers published by the calendars themselves, nothing about any person, and it is lost whenever the Bot restarts.

Logs

The Bot writes operational logs to standard output. These logs record:

  • lifecycle events: connecting, reconnecting, session start and resume, heartbeat health;
  • each scheduled announcement run: whether it was the daily or the weekly one, how many events each calendar returned, how many were announced, and when the next run is due;
  • the name of each command that fails or is not recognised — not its arguments;
  • diagnostic error text, which can include identifiers generated by Discord for the failed request.

Logs do not record message content, Discord user IDs, usernames, or the values you pass to command arguments.

Logs exist for operating and debugging the service. They are shipped to Amazon CloudWatch Logs in the us-east-1 region and are deleted automatically after seven days. They are not exported anywhere else, analysed for behaviour, or shared.

Who else is involved

  • Discord. The Bot is a Discord application and everything it receives arrives through Discord’s platform. Your use of Discord is governed by Discord’s Privacy Policy.
  • The hosting provider running the Bot’s container, which necessarily processes the traffic and logs described above.
  • Amazon Web Services, which stores the operational logs described above (CloudWatch Logs, seven-day retention) and serves this website. Standard web access logs may be produced for the pages you are reading now; they are not linked to your Discord account.
  • The event calendars the Bot reads once a day: the CNCF community group calendar, run by the Open Community Groups project, and the Linux Foundation’s conference calendar. The Bot only reads their public listings. It sends them nothing about you, holds no account with either, and neither of them learns that you exist.

There are no analytics services, advertising networks, or trackers. We do not sell, rent, or trade data, and we do not use it to train machine learning models. Because the Bot is an educational tool, it is worth being explicit about what that rules out: it builds no profile of you, keeps no record of which learning material you asked for, and measures no one’s progress or participation.

Your choices and rights

Because the Bot stores no personal data, there is normally nothing to export or erase. Removing the Bot from a server stops all processing immediately and leaves nothing behind.

If you believe the Bot holds data about you, or you want to ask about access, correction, erasure, restriction, objection, or portability, write to kenesparta@pm.me. We will respond within 30 days. Depending on where you live, you may also have the right to complain to your local data protection authority.

Legal basis for processing

Where the UK GDPR or EU GDPR applies, the Bot processes interaction data on the basis of legitimate interests (Article 6(1)(f)): responding to a command you deliberately invoked, and keeping the service running and secure. You can withdraw from this processing at any time by not using the Bot’s commands.

The Operator is based in Peru, where Ley N.° 29733, the Ley de Protección de Datos Personales, applies. Running a command is a deliberate act on your part, and the Bot builds no personal data bank (banco de datos personales) because it stores nothing.

Children

The Bot is not directed at children. Discord requires users to be at least 13 years old, or older where local law sets a higher minimum. Do not use the Bot if you do not meet Discord’s minimum age.

Security

Because no user data is retained, there is no user data at rest to breach. Operational credentials such as the Bot’s Discord token are stored encrypted and are decrypted only into the memory of the running process. No system is perfectly secure, and we cannot guarantee absolute security.

International transfers

The Bot’s operational logs are stored in the United States (AWS us-east-1), which may not be your country of residence. Discord likewise operates internationally. Given that no user data is retained and the logs hold no user identifiers, the practical exposure of any such transfer is limited to the transient processing described above.

Changes

We may update this policy. The current version always lives at cnayp-bot.kenesparta.dev/privacy.html, with the “last updated” date at the top. Material changes will be announced in the servers where the Bot is present, where that is practical. Continuing to use the Bot after a change means you accept the updated policy.
